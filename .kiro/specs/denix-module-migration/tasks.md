# Implementation Plan

## 全タスク共通のフェーズゲート

各 Major タスク (= Phase) は独立してコミット可能な単位とする。タスク完了時に以下を実行し、
すべて通ることを完了条件とする。失敗した場合は次の Major タスクへ進まず当該タスク内で修正する。

- `nix flake check`
- `nixos-rebuild build --flake .#comabook` および `.#wsl`
- `home-manager build --flake .#Home`
- `nix store diff-closures` による移行前後の差分確認 (差分は列挙し原因を説明できること)

機能追加・パッケージのバージョン更新を移行の変更に混ぜない。設定内容の改善はタスク 11 完了後に行う。

_Requirements: 1.1, 1.2, 1.3, 1.4, 1.5, 1.7_

---

- [ ] 1. Phase 0: デッドコードと impure 評価の除去

- [x] 1.1 (P) 未参照ファイルを除去する
  - `flake.nix` から到達不能なファイルを除去する。対象は AI エージェント用の未参照システム設定、
    WSL 向けシステム設定のフォーク、未参照の catppuccin fetch 定義
  - 空の attrset を返すコンテナ定義とその import 文を除去する
  - 除去前に各ファイルが未参照であることを確認し、参照が見つかった場合は除去せず報告する
  - 除去後に comabook の構成が従来どおり評価・ビルドできることを確認する
  - _Requirements: 3.1, 3.2, 3.3, 3.4, 3.5, 3.7_
  - _Boundary: Migration Phases_

- [x] 1.2 (P) impure な nixpkgs 取得を撤去する
  - 旧版 nixpkgs の取得定義とそれを参照する Hyprland パッケージ定義を除去する。両者は他から
    参照されていないため代替は不要
  - unstable 版 nixpkgs の取得定義を撤去し、これを使用している言語モデル実行サービスの
    パッケージ指定を主 nixpkgs 由来のものへ置き換える
  - 作業後に `--impure` フラグなしで全ホストの構成が評価できることを確認する
  - リポジトリ内に impure な tarball 取得が残っていないことを確認する
  - _Requirements: 2.1, 2.2, 2.3, 2.4, 2.5_
  - _Boundary: Flake Entrypoint_

- [ ] 2. Phase 0: 自作パッケージの共通化と flake output 公開

- [ ] 2.1 自作パッケージを標準的なパッケージ呼び出し規約へ移行する
  - `pkgs/` 配下の全13パッケージについて、引数を「パッケージ集合そのもの」から
    「必要な依存のみ」を受け取る形へ変更する
  - ホームディレクトリを引数に取っている同期スクリプト2件は、実行時に環境変数から解決する形へ変更する
  - `lib` を明示的に渡されているパッケージは、標準の依存注入で受け取る形へ変更する
  - 既に標準規約に適合している2パッケージについては、規約変換用の入口ファイルを除去する
  - 全13パッケージが単体でビルドできることを確認する
  - _Requirements: 4.1, 4.3, 4.6_

- [ ] 2.2 (P) 入力由来のオーバーレイと互換性回避策を切り出す
  - `flake.nix` に埋め込まれているオーバーレイ定義を専用ディレクトリへ移す
  - 互換性回避策 (非推奨プラットフォーム判定のシャドウ、ディスプレイ情報ライブラリの旧版供給、
    LDAP パッケージのテスト無効化) を1ファイルに集約し、撤去条件のコメントを維持する
  - 外部パッケージ集合を名前空間付きの属性として提供するオーバーレイを追加する
  - オーバーレイの適用順序を明示的に固定する。順序は互換性回避策 → 入力由来 → 外部集合 → 自作パッケージ
  - オーバーレイ集合が単体で評価できることを確認する
  - タスク 2.1 と異なるファイル群を扱うため並行実行可能。ただし自作パッケージのオーバーレイ登録は
    タスク 2.3 で行う
  - _Requirements: 2.5, 4.7_
  - _Boundary: Overlay Set_

- [ ] 2.3 自作パッケージをオーバーレイと flake output へ一括登録する
  - ディレクトリ再帰走査により `pkgs/` 配下を一括でオーバーレイへ登録する
  - 同じ集合を flake のパッケージ output として公開し、パッケージ名を指定した単体ビルドを可能にする
  - パッケージ集合を再 export するだけの中間ファイル3件を除去する
  - 二重定義されているジャケット画像パッケージをオーバーレイ側へ一本化する
  - モジュール側から「パッケージ定義を直接 import する」記述が消えていることを確認する
  - _Requirements: 4.1, 4.2, 4.3, 4.4, 4.5_
  - _Depends: 2.1, 2.2_

- [ ] 3. Phase 1: denix 基盤とホスト定義の導入

- [ ] 3.1 denix を導入し構成生成の入口を差し替える
  - denix を flake 入力として追加し、nixpkgs と home-manager を本リポジトリの入力へ追従させる
  - 構成生成関数を呼び出す形へ入口を書き換える。ホスト・モジュール・rice の探索パスを指定する
  - standalone home-manager 運用を維持するため、システム構成側への home-manager 統合を無効にする
  - ホスト種別と機能フラグを生成する拡張、およびホスト情報をモジュール引数へ渡す拡張を有効にする
  - 探索パス配下が自動発見されるため、読み込み指定を手書きしないことを確認する
  - システム構成にユーザー環境管理の設定項目が現れないことを確認する
  - _Requirements: 5.1, 5.2, 5.5, 5.7_

- [ ] 3.2 機能フラグの語彙を定義する
  - ホスト種別として デスクトップ / ラップトップ / サーバー の3分類を設定する
  - 機能フラグの初期集合を宣言する。ウィンドウ環境、GUI アプリ、開発環境、Emacs、
    AI エージェント、メディア、コンテナ、分散ビルド、VPN、WSL の10種
  - ホスト種別ごとの既定フラグ集合を宣言する
  - フラグの減算は種別既定値の明示上書きで行う方式を確認する
  - 未定義のフラグ名を指定した場合に評価時エラーになることを確認する
  - _Requirements: 8.3, 8.4, 8.6_

- [ ] 3.3 共有定数とアイデンティティ導出モジュールを作成する
  - ユーザー名、氏名、メールアドレス、ホームディレクトリ、dotfiles リポジトリのパス、
    スクリプト配置先を読み取り専用の共有定数として宣言する
  - ホームディレクトリをプラットフォーム判定で分岐させ、macOS 向けの導出も可能にする
  - ユーザー環境側のユーザー名とホームディレクトリを共有定数から設定するモジュールを作成する
  - システム側および macOS 側のユーザー定義を共有定数から設定するモジュールを作成する
  - 共有定数が再代入不可であることを確認する
  - _Requirements: 7.1, 7.3, 7.4, 7.6, 11.4_

- [ ] 3.4 3ホストの定義を作成する
  - comabook をデスクトップ種別、raspi をサーバー種別かつ AI エージェントフラグ付き、
    WSL をデスクトップ種別かつ種別既定値の明示上書きで作成する
  - WSL については GUI・ウィンドウ環境・メディアの各フラグを無効にする
  - ハードウェア構成ファイルはホスト宣言でラップして配置する。素置きすると全ホストへ
    適用されてしまうため
  - システム状態バージョンとユーザー環境状態バージョンをホスト定義側へ移す
  - ホスト名をモジュール内のリテラルではなくホスト情報から導出する形にする
  - 各ホスト定義にパッケージリストやサービス設定を含めない
  - _Requirements: 8.1, 8.2, 8.5, 7.5, 11.2_

- [ ] 4. Phase 1: 既存設定の暫定ラップと構成名の維持

- [ ] 4.1 既存設定をホストセクションへラップする
  - comabook のシステム設定、comabook のユーザー環境設定、raspi のシステム設定、
    WSL のユーザー環境設定を、それぞれホスト宣言のセクションへ載せる
  - モジュール宣言と条件分岐の組み合わせは使わない。ホストセクションは対象ホストのみに
    適用されるため条件分岐が不要であり、外部モジュール読み込みを含む設定を条件分岐で
    囲むと評価が無限再帰になるため
  - ユーザー環境設定は補助定義ブロックをファイル先頭へ移し、自己参照を含む本体を
    そのままセクションへ渡す
  - 外部ハードウェアプロファイルの読み込みはセクション内の読み込み指定に残す
  - 無効化状態のファイルを作らない。探索対象からの除外指定は使用しない
  - 全ホストがビルドでき、comabook の closure 差分が説明可能な範囲に収まることを確認する
  - _Requirements: 5.6, 1.6_

- [ ] 4.2 構成名のエイリアス層を追加する
  - ユーザー環境構成は「ユーザー名@ホスト名」形式で生成されるため、現行の適用手順で
    使われている3つの短縮名をエイリアスとして公開する
  - システム構成については生成される名前がホスト名そのものであることを確認する
  - 短縮名とエイリアス元の双方でユーザー環境構成がビルドできることを確認する
  - 非フリーパッケージの許可設定がユーザー環境構成で有効になることを確認する。
    無効の場合はユーザー環境向けパッケージ集合の供給方法を差し替える
  - _Requirements: 5.2, 5.4_

- [ ] 5. Phase 2: 基盤とハードウェアの機能モジュール切り出し

- [ ] 5.1 基盤カテゴリを切り出す
  - フォント、Nix の設定と分散ビルド、ロケールと時刻、ネットワーク、
    実行時互換レイヤ、セッション変数を個別のモジュールへ移す
  - 分散ビルド関連は該当フラグで有効・無効を制御する
  - 各モジュールは自身の有効条件を自身で宣言する。ホスト側に条件を書かない
  - 暫定ラップからの該当部分の削除と新モジュールの追加を同一の変更で行う。
    片方だけ行うとオプションの二重定義で衝突する
  - _Requirements: 6.1, 6.2, 6.5, 8.3_

- [ ] 5.2 ハードウェアカテゴリを切り出す
  - 電源管理とスリープ、Bluetooth、オーディオ、印刷、ペンタブレット入力変換を
    個別のモジュールへ移す
  - ペンタブレット関連はシステム側の入力変換サービスとユーザー環境側の
    起動時設定スクリプトを同一ファイルへまとめる
  - ブートローダとカーネル関連の機器固有設定は comabook のハードウェア定義へ移す
  - システム側とユーザー環境側にまたがる機能が単一ファイルで完結していることを確認する
  - _Requirements: 5.3, 6.1, 6.2, 6.3_

- [ ] 5.3 ハードコードされたパスを共有定数経由へ置き換える
  - モジュール内のホームディレクトリのリテラル参照を共有定数からの導出へ置き換える
  - dotfiles リポジトリへのリンク生成をすべて共有定数経由にする
  - リポジトリ内の Nix ファイルにホームディレクトリのリテラルが残っていないことを確認する
  - _Requirements: 7.1, 7.2, 7.4_

- [ ] 6. Phase 2: プログラムとサービスの機能モジュール切り出し

- [ ] 6.1 プログラムカテゴリを切り出す
  - シェル、Emacs、ターミナルエミュレータ2種、ファイル表示、パッケージ索引、
    暗号エージェント、Web ブラウザを個別のモジュールへ移す
  - Emacs モジュールは常駐プロセス定義、デスクトップエントリ、
    起動時のバイトコンパイルと構文解析データ生成をすべて同一ファイルへまとめる
  - 各モジュールが自身の設定ファイルへのリンクを自身で保持する形にする
  - _Requirements: 6.1, 6.2, 6.3_

- [ ] 6.2 サービスカテゴリを切り出す
  - 言語モデル実行、キー入力変換、VPN、認証同期、DNS、仮想化、音楽再生、
    履歴管理、クラウド同期を個別のモジュールへ移す
  - クラウド同期は常駐サービスと定期実行タイマーを同一ファイルへまとめる
  - 外部モジュールの読み込みは無条件に行い、有効化オプションのみをフラグで制御する。
    条件分岐内で読み込むと評価が無限再帰になるため
  - 各サービスが対応するフラグで有効・無効になることを確認する
  - _Requirements: 6.1, 6.2, 6.5_

- [ ] 7. Phase 2: パッケージ束の option 化

- [ ] 7.1 パッケージ束をモジュールへ変換する
  - リスト返し関数として定義されている11ファイルを、有効化オプションを持つモジュールへ変換する
  - 呼び出し側からパッケージ集合以外の引数を受け取らない形にする。カスタム Emacs と
    外部パッケージ集合はオーバーレイ経由で解決する
  - システム寄りのパッケージ群をシステム側のパッケージ指定へ移す
  - ユーザー寄りのパッケージ群はユーザー環境側のパッケージ指定に残す
  - 分類不能なパッケージの集積ファイルを解体し、各束へ再分類する。同名の新規ファイルは作らない
  - リスト返し関数形式の定義がリポジトリに残っていないことを確認する
  - _Requirements: 9.1, 9.2, 9.3, 9.5, 9.6_

- [ ] 7.2 パッケージ束をフラグへ接続する
  - 開発環境、エディタ、GUI アプリ、メディア、ウィンドウ環境、AI エージェントの各束を
    対応するフラグへ接続する
  - ターミナル、汎用ユーティリティ、バージョン管理、セキュリティの各束は常時有効とする
  - あるフラグを無効にしたホストで、当該束のパッケージが構成の closure に含まれないことを確認する
  - _Requirements: 9.4, 8.4_

- [ ] 8. Phase 2: デスクトップ環境の切り出しと暫定ラップの撤去

- [ ] 8.1 デスクトップカテゴリを切り出す
  - キーボード配列、ログイン画面とセッション選択、デスクトップ統合ポータル、
    タイル型ウィンドウ環境、代替ウィンドウ環境を個別のモジュールへ移す
  - タイル型ウィンドウ環境のモジュールは、システム側の有効化、設定ファイルへのリンク、
    常駐ヘルパ2種、ステータスバーと通知を同一ファイルへまとめる
  - 現在使用していないウィンドウ環境の設定は隔離ディレクトリへ移し、フラグを無効にする
  - _Requirements: 3.6, 6.1, 6.2, 6.3, 6.6_

- [ ] 8.2 テーマ設定を rice へ集約する
  - システム側とユーザー環境側に散在しているテーマ設定を単一の rice 定義へ移す
  - 配色、アクセント色、壁紙を rice の設定項目として宣言する
  - comabook のホスト定義で当該 rice を既定指定する
  - rice は1個に限定する。rice ごとに追加の構成が生成され検証時間が線形に増えるため
  - _Requirements: 6.1, 6.2_

- [ ] 8.3 設定ファイルリンクを各機能モジュールへ分配し暫定ラップを撤去する
  - ユーザー環境設定の 336 行に及ぶファイル配置定義を、各機能モジュールへ分配する。
    分配先は「その設定ファイルを使う機能のモジュール」とする
  - 辞書データ、構文解析データ、言語サーバー向けの安定パスなど機能に紐づかない配置は
    対応するプログラムモジュールへ寄せる
  - 分配完了後、暫定ラップのディレクトリをまとめて除去する
  - 暫定ラップのディレクトリが存在しないことを確認する
  - 1回の変更で複数カテゴリを同時に移動させない
  - _Requirements: 6.4, 6.7_

- [ ]* 8.4 同一フラグ集合のホスト間で構成が一致することを検証する
  - 同一のフラグ集合を宣言した2ホストに対し、適用されるモジュール集合が一致することを確認する
  - 検証は一時的なホスト定義を用いて行い、確認後に除去する
  - 受け入れ条件 8.6 に対応する補助的な検証であり、コア実装の完了後に実施できる
  - _Requirements: 8.6_

- [ ] 9. Phase 3: 機密情報管理のモジュール化

- [ ] 9.1 復号鍵の基盤モジュールを作成する
  - システム側はホストの SSH ホスト鍵を復号鍵として使用する設定を行う
  - ユーザー環境側は既存の age 鍵ファイルを復号鍵として使用する設定を行う
  - 二系統の鍵方式を並行して維持する。個別の機密情報の宣言はこのモジュールに含めない
  - 機密情報管理の外部モジュール読み込みを無条件で行う
  - _Requirements: 10.5, 10.10, 10.11_

- [ ] 9.2 機密情報の宣言を消費モジュールへ移す
  - ユーザー環境側の4件の機密情報を、それぞれを使用するモジュールの中で宣言する
  - raspi の機密情報とテンプレート、および対応する常駐サービス定義を
    当該サービスのモジュールへ一括で移す
  - 配置先パスの明示指定を外し、機密情報管理ツールの既定パスに委ねる。
    これにより利用者 ID のリテラルが除去される
  - 消費側は宣言された機密情報のパス属性を参照する形にする
  - システム側のテンプレートには所有者と権限を明示する。ユーザー環境側は権限のみを明示する
  - 利用者 ID のリテラルがリポジトリに残っていないことを確認する
  - _Requirements: 10.1, 10.2, 10.3, 10.6_

- [ ] 9.3 平文経路とハードコードされた資格情報を除去する
  - 平文の機密情報をファイルシステムへ複製し権限を変更している起動時スクリプトを廃止し、
    テンプレートの出力パスをネットワーク管理サービスへ直接参照させる
  - raspi の初期パスワードのリテラルと、パスワード確認の無効化設定を廃止し、
    ハッシュ化パスワードのファイル参照へ置き換える
  - 機密情報を必要とするサービスを当該パスへ依存させ、復号失敗時に起動しない構成にする
  - 平文複製スクリプトとパスワードのリテラルが残っていないことを確認する
  - _Requirements: 10.4, 10.8, 10.9_

- [ ] 9.4 暗号化対象の鍵グループをホスト単位へ分離する
  - 機密情報の作成規則をホスト単位のパスで分離する。raspi 用、comabook 用、
    ユーザー環境用の3グループとする
  - 各 NixOS ホストの SSH ホスト鍵から age 公開鍵を導出し、対応する鍵グループへ登録する
  - 鍵グループの変更後に全対象ファイルの再暗号化を実行する
  - raspi 実機で復号が成功することを確認する。再暗号化の漏れは復号不能を招くため
    この確認を完了条件とする

## 並行実行に関する補足

Phase 2 (タスク 5 〜 8) の各サブタスクは暫定ラップの同一ファイル群を編集するため、
並行実行不可とする。切り出し元からの削除と切り出し先への追加を同一の変更で行う必要があり、
複数タスクが同時に同じ暫定ラップを編集するとオプションの二重定義による衝突が発生する。

Phase 3 (タスク 9) の各サブタスクは、機密情報の宣言内容と鍵グループの整合を保つ必要があるため
並行実行不可とする。特に鍵グループの変更と再暗号化は、宣言済みの機密情報が確定した後に行う。
